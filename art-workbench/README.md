# 观物 · 中国美学与 AI 美术工作台

面向用 AI 制作游戏和 App 的创作者，把中国古代美学研究与实际美术制作放在同一个工作台。研究帮助解释一种风格为什么成立；制作工具把这些依据转成可复用的简报、素材规格、色板和检查项。

这里暂不确定游戏类型，也不把既有游戏的设定当作前提。重点是形成有出处、有视觉规则、能在角色、场景、图标和界面之间延续的美术语言。

## 五个工作区

| 工作区 | 你可以做什么 | 留下什么 |
| --- | --- | --- |
| 研究馆 | 检索与比较 12 条美学路线，了解时代、媒介、构图、造型、材料与设色 | 有出处的主样本、对照样本与需要继续核查的问题 |
| 深研室 | 沿具体作品或对象组拆解结构，做单变量 A/B 实验，检查常见 AI 失误 | 研究笔记、参数记录、人工审校清单与制作约束 |
| 制作台 | 将研究实验传入游戏或 App 素材简报，编辑正负向描述、规格与颜色职责 | 可复制提示词、Markdown 简报、JSON 颜色与研究参数 |
| 检验室 | 在浏览器内读取实际图片，分析尺寸、透明度、主色与文字对比度 | 图像分析记录；帮助识别素材与界面的一致性问题 |
| 项目册 | 保存简报、研究参数与手动修改，恢复制作并导入导出 | 浏览器本地项目与独立 JSON 备份 |

## 深研室：从一种感觉到可检查的规则

12 份对照档案分别围绕漆器、画像石、青绿山水、南宋小景、花鸟、宋瓷、敦煌、园林、木版、明式木作、书法和青花展开。档案会区分主例和对照、历史线索和结构解释、现代制作假设；有些主例仍是待选择单件的对象组，不声称已经完成 12 件文物的全面考证。

每条路线提供 6 项制作约束、3 项单变量 A/B 任务、AI 失误的症状与修正步骤，以及人工审校问题。合计 72 项制作约束和 36 项实验任务，用来回答“要固定什么、只改变什么、怎样判断这次变化有用”。参数和检查项都是现代项目建议。

例如研究青绿山水时，先比较连续展开中的岸线、开放水面与生活节点，再用灰阶结构练习改变近景尺度；检验地标和方向是否仍然清楚。研究漆器时，先看器口、内腔与把持部，再改变纹饰覆盖比例，检查装饰有没有吞没用途。这样的实验可以给 AI 简报增加可执行约束，也可以帮助判断一张图为什么虽漂亮却不能用。

互动结构练习使用山水空间、器物轮廓和线色组织三类原创 SVG，并随路线调整问题与说明。可以对照 A/B、查看灰阶和结构线、记录观察，再把当前参数传入制作台。它们不是原作临摹、实物测量、历史比例标准或自动审美评分；某条路线的详细实验任务也不都已实现成互动仿真。

建议先走一轮：选择路线 → 读主例与对照 → 只调整一个变量 → 写下观察并人工审校 → 传入制作台 → 用自己的图像工具出图 → 回到检验室检查 → 保存项目和研究笔记。研究笔记可导出 Markdown/JSON；项目保存会保留进入简报的研究参数及手动编辑。详见 [研究方法](docs/research-method.md) 与 [深研内容说明](docs/deep-study.md)。

本版本未连接 AI 模型 API。它帮助研究、规划和检查美术，页面中的制作描述需要由创作者用于自己选择的图像工具。研究图的生成与来源说明见 [美术来源](docs/ART-SOURCES.md)。

## 出处与引用状态

资料的 `reference` 状态表示参考线索；`verified` 表示已按记录核对某条具体官方来源。37 条核心来源中，11 条已通过故宫、台北故宫数字典藏或数字敦煌具体页面核对，26 条仍为参考线索。核对页面、时间、字段和范围见 [出处核验记录](docs/evidence-audit.md)。不把“网站可以打开”当作艺术史结论验证，也不把引用状态当作图像授权。

来源记录得到核验，不会自动使引用它的所有结构解释和现代制作假设都成为历史事实。深研档案保留各项线索与限制；传统归属、年代争议、材料与工序未确认之处继续写明。数字颜色是工作色板，不是古代颜料或釉色的科学测量值。

馆藏作品、博物馆资料和外部参考链接需要网络。有些馆站可能受当前云环境的域名策略、地区或反爬限制；不可访问的来源保留参考状态和说明。正式制作还需要对服饰、器物、纹样和时代对应关系继续核查。

## 开发环境

使用 Node.js 20.19 及以上版本，或 Node.js 22.12 及以上版本；构建使用项目锁定的 React、Vite 与 TypeScript 依赖。单文件 ZIP 打包还需要 Python 3，仅使用其标准库。

在 `art-workbench` 目录运行：

```sh
npm ci
npm run dev
```

开发服务默认监听端口 `4173`。也可以使用启动脚本指定端口：

```sh
PORT=4173 bash tools/serve.sh dev
```

生产构建及预览：

```sh
npm run build
PORT=4173 bash tools/serve.sh preview
```

`tools/serve.sh` 遇到端口占用会明确失败，不会悄悄换端口。云环境中的访问地址以环境实际提供的预览入口为准。

## 单文件离线交付

```sh
npm run build:portable
```

这个命令先构建静态站，再以 `PORTABLE_BUILD=1` 运行项目的本地 Vite，生成内嵌脚本、样式与图像的单文件 HTML。交付脚本检查 HTML 与内联资源，拒绝残留的外部加载资源，再生成 ZIP 并校验 CRC。

输出：

- `dist/`：用于静态站托管的生产文件。
- `release/guanwu-art-workbench.html`：可双击打开的离线页面。
- `release/guanwu-art-workbench.zip`：HTML、使用说明与许可证说明。
- `release/release-manifest.json`：文件大小、SHA-256 与打包检查记录。

离线页面的研究与制作工具无需网络；点击来源链接仍需联网。`file://` 页面在不同浏览器、隐私窗口或文件路径下可能使用不同本地存储空间。移动文件和清理浏览器数据前先导出项目。

当前环境的 Chromium 管理策略阻止访问 `file://`，因此本地文件模式尚未在此环境实测。最终浏览器验收使用 HTTP 载入与交付 HTML 完全相同的字节，再断网检查图片与交互；这项检查不能替代用户电脑上的本地文件验证。无需修改或绕过管理员策略。

资源静态检查证明包内没有检测到外部加载引用；浏览器验收进一步检查运行行为。当前检查结果与实际限制见 [交付说明](docs/DELIVERY.md)。
