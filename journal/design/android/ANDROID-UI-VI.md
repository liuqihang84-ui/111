# 一日一笺 · Android UI / VI 设计规范

版本：设计方案 0.1 · 2026-10-04 · 状态：UI / VI 设计稿交付；未开发 Android / APK。

这份规范确定独立 Android 电子手账的品牌语言、页面结构、控件和验收方法。它不是网页缩小版，也不是给现有网页加一个安装外壳。本轮只设计 UI / VI；尚未实现 Android 界面，不提供 APK，不以设计稿替代运行结果。项目名暂用「一日一笺」。Compose、Flutter 或其他实现方式留到方案确认与技术验证时选择。

设计稿中的记录、照片、日期和任务均为演示内容，必须在画板旁标注「示例内容」。首次安装默认空白，不预填这些记录；生成素材也不代表用户拍摄的照片。

## 1. 设计立场

产品是一款记录日常的数字手账：拿起手机即可记录，读回内容时安静、清楚，照片和文字有自己的节奏。东方气质来自留白、虚实关系、非对称构图、温润材质与字形节制，不依靠山水底图、印章、古器堆砌或仿纸纹理。

视觉方向是「暖白中的苍墨，少量玉质折光」。页面本身清爽，3D 只出现在能建立品牌记忆或解释状态的位置。文字、输入框、照片和列表不能因为材质展示而难读。避免灰绿铺满全屏、泛黄纸张、桌面文具、网页式大横幅、漂浮多张倾斜内容板，以及所有按钮都做成胶囊的处理。

核心感受依次为：容易记录、读得舒服、轻而有空间感、具有自己的识别度。精致来自比例、对齐、字重、边界和一致的反馈；不能只靠模糊、阴影或渐变制造。

## 2. 品牌 VI：折光弧

### 2.1 母形

「折光弧」是一枚抽象的单体玉质弧形透镜。统一母形为前视图的圆角开口弧，右上保留清楚缺口；弧形切面形成受控的厚薄变化与折射高光。只出现一个主体，不能画成闭合玉环、两叠书页、两张卡片、一本小册子或古代玉器的写实复制。

造型固定三个特征：

1. 单体轮廓：前视图为圆角开口弧，端部圆润，右上缺口在 24–32 dp 仍可清楚辨认；不使用尖角和平面断裂。
2. 弧形切面：材质切面和光线沿同一母弧展开，保留轻微虚实变化；不改变开口方向，不用透视将缺口遮成闭环。
3. 同向光：光线始终从左上进入，右下仅留浅色边缘，内部可见少量浅玉色折光。没有珠光闪粉和高强度霓虹。

这是现代品牌造型，借用温润与虚实的审美感受，不宣称还原某件古器、某朝代工艺或具有考据结论。相关文化研究可以作为独立资料，不放进操作界面充当装饰。

### 2.2 平面与 3D 版本

| 版本 | 用途 | 规则 |
| --- | --- | --- |
| 单色母形 | 24–32 dp 小图标、设置标题、无动画降级 | 苍墨实形或线形；保留偏心弧，去掉渐变和阴影 |
| 双色母形 | 品牌锁定、启动静态画面 | 玉色主体 + 暖白切面；边界仍清楚 |
| 3D 母形 | 品牌展示、首次空态或主操作的轻反馈 | 半透、有适度厚度，轻微折光；展示面积有限，不能压住主要内容 |
| Android 应用图标 | 系统桌面、应用抽屉 | 独立前景、背景及单色层，接受系统自适应遮罩；不要在图标内排完整中文品牌名 |

品牌锁定为「折光弧 + 一日一笺」。中文品牌名为单行，小尺寸时优先保留清楚文字，不额外添加英文副标、口号和解释性小字。母形与文字间距为母形宽度的 1/3；四周安全区至少为母形宽度的 1/2。组合最小高度为 28 dp；仅母形最小高度为 24 dp。

Android 自适应图标按 108 × 108 dp 分层画布制作，关键母形落在居中的 66 × 66 dp 安全区域内，并验证圆形、圆角矩形及厂商遮罩。常规背景用暖白，主体用玉色与苍墨；单色主题图标应使用独立轮廓，不将一张带阴影图片灰度化。

### 2.3 不允许的品牌变体

不能随页面改变母形弧线方向、材质色温或光源。2D、3D、应用图标都沿用同一开口轮廓，不能出现「2D 尖角开口、3D 光滑闭环」的两套标记。不能用现有叠页标记替代折光弧，也不能在每条记录、每个按钮、每个分隔线旁重复放玉形。删除各页右上没有操作意义的玉环；品牌识别集中在应用图标、品牌展示、少数空态和导出署名，正文保持内容优先。

## 3. 色彩与基础 tokens

### 3.1 调色板

| Token | 数值 | 用途 |
| --- | --- | --- |
| `color.canvas` | `#F8F7F2` | 全局暖中性背景；首页和编辑页主要面积 |
| `color.ink` | `#163D36` | 主文字、主要图标、主要按钮、选中态 |
| `color.jade` | `#9CC6B3` | 品牌透镜、小范围选中底、轻材质，不作常规浅色正文 |
| `color.boundary` | `#DBE4D8` | 装饰分界、非必要描边、轻分隔 |
| `color.accent` | `#BC745E` | 极少量暖色强调，如今日小点或一句回顾标记 |
| `color.textSecondary` | `#58685F` | 次级文字和辅助说明，不能继续降低不透明度 |
| `color.focus` | `#496E5E` | 键盘焦点、需要明确识别的控件边界 |
| `color.error` | `#8E493A` | 保存失败文字、错误图标；源自暖色强调的较深语义色 |
| `color.surface` | `#FFFFFF` | 必要的高一级表面，少量使用 |

浅背景至少占常规页面可见面积的 75%。苍墨集中在文字和行动；玉色用于少量形体或状态。暖色强调单页只服务一种重点，不出现彩色徽章集合。不要把整块编辑区染成深绿，也不要以降低正文透明度表现「轻盈」。

基础不透明 sRGB 对比度参考：苍墨 / 暖白约 11.16:1，苍墨 / 玉色约 6.35:1，次级文字 / 暖白约 5.50:1；暖色强调 / 暖白约 3.38:1，浅边界 / 暖白约 1.22:1。暖色强调不能直接作为 16 sp 正文，浅边界不能单独承担输入框、选中态或焦点的必要识别。半透明、图片背景和最终渲染颜色需重新计算，不能沿用这组数值。

深色方案为可选设计探索，不是现有 App 功能。预备 tokens：背景 `#111F1C`、表面 `#1C2D28`、主文字 `#EDF0E8`、次级文字 `#B5C6BB`、玉色强调 `#9CC6B3`、分隔 `#3B5148`。深色不直接反转浅色 RGB，也不能让玉质形与正文一起发亮。仍需全状态精稿和最终渲染对比度检查，未在设备上验证。

### 3.2 间距、圆角、深度

| 类别 | Tokens | 说明 |
| --- | --- | --- |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48 dp | 以 4 dp 为基准；同类组件保持相同间距 |
| 页面左右边距 | 360 / 412 dp 均为 24 dp | 内容宽分别为 312 dp、364 dp；日历网格采用下文专用边距 |
| 区块间距 | 24 或 32 dp | 导航、标题、列表之间保留结构，而不是到处加容器 |
| 圆角 | 控件 12 / 内容 16 / 弹层 24 dp | 与 `design-tokens.json` 一致；整圆只留给圆点及必要的悬浮入口 |
| 分隔 | 1 dp | 低强度边界用于次要结构，重要控件另用文字或清晰边界 |
| 平面层级 | 0 / 1 / 2 | 页面本身无阴影；弹层与焦点可有轻度层次 |
| 3D 形体阴影 | 低透明度、近距离软边 | 只支撑一个形体的悬浮感；不画桌面接触影和摄影景深 |

相同交互类型使用相同形状。主要按钮不是胶囊；文字按钮和图标按钮无需增加彩色底。列表不套多层卡片、容器、描边和阴影。

## 4. 字体与排版

正文、导航、日期、按钮及输入全部使用 Android 清楚的中文无衬线字体；优先系统中文 sans。若选择 Noto Sans SC，应提供适合 Android 的字体格式与完整所需字形，并保留其许可证，不能只引用在线字体链接。当前项目尚未为原生 App 引入 Noto Sans SC 文件。

现有 `src/assets/guanwu-serif.woff2` 是 Guanwu Serif 的 Web 子集资源，来源记录为 Noto Serif SC 重命名衍生子集，许可证与版权声明见 `src/assets/FONT-LICENSE.txt`。它只用于品牌字标或短页面标题点缀；不能作为长正文、任务内容、输入默认字体或导航字体。原生端需要再确认可用字体文件、字形覆盖和许可，不能直接把 Web 子集视为原生字体准备完成。

| 角色 | 默认字号 / 行高 | 字重 | 规则 |
| --- | --- | --- | --- |
| 品牌字标 | 20 / 28 sp | 常规或中等 | 字标可用衬线点缀，保持单行与清晰 |
| 页面主标题 | 28 / 36 sp | 中等 | 首页「今天」、回顾月份；短标题可用衬线 |
| 编辑标题 | 24 / 34 sp | 中等 | 输入用 sans，允许换行；不能截掉用户内容 |
| 列表标题 | 18 / 26 sp | 中等 | 内容标题；无标题记录直接显示正文摘要 |
| 正文 / 编辑正文 | 16 / 26 sp | 常规 | 字色苍墨，不用细字重 |
| 操作 / 导航 | 14–16 / 22–24 sp | 中等 | sans；主操作默认 16 sp、导航可 14 sp；触控范围另按 48 dp 处理 |
| 日期 / 月历数字 | 14–16 / 22–24 sp | 常规 | sans；主要日期默认 16 sp，次级标记可 14 sp，不回退到衬线数字 |
| 保存状态 / 辅助说明 | 14 / 22 sp | 常规 | sans、次级文字色；关键失败提示使用 16 sp |

正文不增加大字距。最多两种字族、三个实际字重。禁止为了古意而使用难读的书法字、长段衬线或伪竖排输入。

200% 字体缩放是布局验收条件，不能锁定系统字号。页面标题、按钮和列表按内容增长；固定高的单行容器不能挤压文字。底部标签至少保证完整显示，必要时增加导航高度；编辑正文可滚动，内容不能因键盘或保存状态被覆盖。

## 5. 原生 Android 布局基础

### 5.1 尺寸与系统区域

以 360 dp 与 412 dp 宽度分别绘制和检查，画板高度是展示条件，不代表每台设备固定高度。横向与更宽窗口先保持内容最大可读宽度；平板、多窗口布局单独设计，不把手机页随意放大。

系统状态栏与手势导航栏由系统提供，颜色和图标亮度匹配暖白背景。设计稿可画系统占位，但不能把状态栏时间、电量或底部手势线当作 App 控件实现。实际布局读取 WindowInsets，不硬编码系统栏高度；内容、底部导航及弹层均处理系统安全区和 cutout。

顶层页面 App bar 的基准高 56 dp；底部导航基准高 80 dp，加上系统底部 inset。系统栏、App bar 和底部导航是不同层级。按键、图标按钮、日期单元等最小实际触控目标为 48 × 48 dp，视觉图形可以小于触控目标，相邻目标不重叠。原生系统返回、返回手势和导航栈需要一致行为。

### 5.2 顶层导航

底部只有「今日 / 回顾 / 我的」三项，用目的地命名，避免底部的「记录」和编辑操作含混。当前页用苍墨图标与文字表达，可加一枚局部浅玉选中底，但不铺满整条底栏。不用多枚抢眼的悬浮按钮与底部导航竞争，也不把「旧画布」作为顶层导航。

「今日」进入今天列表；「回顾」进入月历与已记录日期；「我的」集中设置、数据备份与隐私说明等。我的页面本轮只确定列表型结构和一致控件，不把未实现能力画成可用状态。旧网页功能与旧数据如何迁移，需要下一阶段单独核对，设计稿不代表已经兼容。

进入记录编辑页时隐藏底部导航，显示原生返回/关闭及保存状态。编辑是全屏页面，不是右侧栏、桌面窗口或盖在网页上的面板。

### 5.3 键盘与输入

键盘弹出时使用真实 IME insets。正文焦点与光标保持可见；编辑辅助栏贴在键盘之上，键盘收起后移到页面底部安全区。标题和正文区域能够顺畅滚动，不在每次保存时自动跳回顶部。输入法 composing text 尚未提交时不能破坏合成字符。

返回第一次可由系统收起键盘，之后回到列表；若仍有未保存修改，使用明确的「继续编辑 / 放弃修改」或持久化草稿流程，不能静默丢内容。具体保存机制由下一阶段选定，但失败必须有可恢复的界面状态。

## 6. 图标系统与组件

### 6.1 图标 24 dp 网格

常用操作图标在 24 × 24 dp 网格绘制，关键形体位于约 20 × 20 dp 的内部区域，基准笔画 1.75 dp，端点和转角风格一致。小尺寸避免两条间距过近的细线；不得混用一套圆润实心图标与一套尖角线描图标。系统行为优先沿用熟悉的语义：返回、关闭、照片、更多、日历。

未选中导航以线形为主，选中可用同一母图的加重或受控实形版本。自有品牌母形不充当所有操作图标。独立图标按钮必须有 TalkBack 名称，例如「添加照片」，不能仅朗读图形或颜色。

### 6.2 组件规范

| 组件 | 结构 / 尺寸 | 主要状态 |
| --- | --- | --- |
| 主按钮 | 基准高 56 dp、12 dp 圆角；苍墨底、暖白文字；水平内边距 20 dp | 默认、按下、不可用、处理中；长文或大字体允许增高 |
| 次按钮 | 48 dp 最小命中；暖白底、苍墨文字，必要时使用明确焦点边界 | 默认、按下、焦点、不可用；不靠浅边界表达唯一状态 |
| 图标按钮 | 24 dp 图形、至少 48 dp 命中区 | 默认、按下、TalkBack 焦点；无意义操作直接不出现 |
| 记录列表项 | 无阴影外框；时间、标题/摘要、可选照片或小事 | 按下反馈、键盘焦点、真实媒体缺失；长内容可展开阅读 |
| 原生标题输入 | 24 sp sans，底线/整框按需，不把占位当唯一标签 | 空白、输入、聚焦、错误；用户标题允许多行 |
| 原生正文输入 | 16 / 26 sp，无纸纹或透镜背景 | 空白、输入、选区、键盘、恢复；光标和选区颜色清晰 |
| 小事项 | 至少 48 dp 高；20–24 dp 勾选图形，正文 16 sp | 未完成、完成、按下；完成状态同时用勾与文字说明 |
| 照片预览 | 16 dp 圆角；按原图比例受控裁切 | 加载、可查看、加载失败、移除；裁切前可确认，不拉伸图片 |
| 月历日期 | 每个有效单元至少 48 × 48 dp | 普通、今天、选中、有记录；状态不可只靠颜色 |
| 保存状态 | 编辑顶栏/邻近操作区域的简短文字 | 保存中、已保存、未保存、保存失败；不覆盖输入内容 |
| 底部操作弹层 | 顶部 24 dp 圆角；列表项至少 48 dp，系统 inset | 打开、关闭、键盘/返回；不叠多层模态窗口 |

按钮加载时保留原语义，可使用小型转圈与「保存中」，禁止只剩一个无名称图标。不可用状态也需可理解的文案或上下文；关键内容不通过低透明度藏起来。

## 7. 三个关键页面

### 7.1 今天：记录列表

页面目标是在一眼内看清今天有什么，并在一次点击后开始写。主视觉是实际内容的排版，不是展柜式 3D 场景。

结构从上到下：系统状态栏 → 简洁顶栏 / 今天标题 → 一行日期与必要筛选 → 记录列表 → 明确的「记一笔」入口 → 三项底部导航。顶栏不额外放无操作作用的玉环；母形只在真正空态或独立品牌展示作为单体形出现。

记录由浅时间线或清楚的时间标签组织。文字记录显示标题或摘要；有照片的记录显示一张正常比例图片；小事用真实勾选状态显示。它们共享文字栅格与留白，不必都套相同大卡片。照片旁不额外加入仿胶带、图钉、纸角或材质标签。正文摘要默认最多三行，点进后读完整内容，200% 字体时保持行数或扩大列表项，不将字体缩小。

有内容时「记一笔」入口不压住最后一条记录；列表末尾预留相应空间。空态只有一枚小型折光弧、一句「今天，还没有记录」与一个「记一笔」按钮，这是空态的唯一主动作；不添加第二个重复入口、示例数据、假统计或劝诱打卡。

### 7.2 记录编辑：真正的全屏输入

从「记一笔」进入全屏页。顶部左侧返回，右侧保存或清楚保存状态；下方是可编辑标题和正文。正文占据主要面积，以正常字距与稳定行高显示，不放在一张倾斜纸或半透明玉板内。

照片、小事是同一条记录中的可选内容区。底部辅助栏只保留本轮需要的「照片」「小事」等少量入口，未加入内容时不显示空的照片框或假任务列表。入口调用后出现可操作内容，取消后回到原状态。日期选择为原生可读弹层，不用旋转 3D 日期轮。

用户选择已有照片后，预览展示实际照片与必要的查看/移除入口。禁止先摆一张风景图来代替用户照片；访问权限未允许或用户取消选择时，不制造假占位卡。输入焦点处的材质效果关闭，避免文字随 GPU 动画晃动。

键盘弹出后界面依然完整：顶部状态不被挤出，当前输入行可见，辅助栏在键盘上方。保存中仍可按选定策略输入；保存失败保留整段内容并提供「重试」。删除、放弃修改等不可恢复动作使用明确确认，普通返回和浏览不增加无谓确认。

### 7.3 月历回顾：日期与内容的关系

上方是月份与左右月切换，中间是可达的七列月历，下方是选中日期的记录列表。月历默认以周一为第一列，显示一行明确星期名称；可配置规则如后续提供，需同时改变读屏标签与日期计算。

今天使用小型暖色标记和文字语义，选中日期使用浅玉背景与苍墨数字，有记录日期增加一个小点并向 TalkBack 提供「有记录」信息。只有选择圈颜色而无其他语义不够。不要把历史数量绘制成假热力图或在没有数据时编造回顾摘要。

360 dp 宽度下，24 dp 左右边距留下 312 dp，无法容纳七个不重叠的 48 dp 日期目标。月历网格采用专用横向边距：360 dp 使用 8 dp，两边共 16 dp，网格宽 344 dp，七列各约 49.14 dp；412 dp 使用 31 dp，两边共 62 dp，网格宽 350 dp，七列各为 50 dp。月份标题与下方列表仍用常规 24 dp 边距。专用月历边距不套用于其他页面，不得通过重叠命中框假称达标。

200% 字体下日期单元高度允许增长，数字不得裁切；必要时使用月份日期列表视图，保留完整日期与有记录状态。系统返回从记录详情回到原选中日期和滚动位置，不能每次跳到今天。

## 8. 状态与反馈

| 情况 | 视觉与文案 | 行为 / 无障碍 |
| --- | --- | --- |
| 首次空白 | 小折光弧、「今天，还没有记录」、「记一笔」 | 没有默认记录、照片、小事或连续天数 |
| 日期无记录 | 「这一天还没有记录」与必要的新建入口 | 保留当前日期；不切回今天 |
| 内容加载中 | 保留页面结构，最多使用简洁骨架或原生进度反馈 | 不重复播放品牌 3D；读屏只宣布一次必要状态 |
| 照片加载中 | 保留实际照片比例区域，局部进度 | 文本和其他记录仍可操作 |
| 无照片 | 完全没有照片区域 | 「添加照片」在编辑辅助栏，不能出现灰色相框来占空间 |
| 照片读取失败 | 「照片暂时无法读取」及「重试 / 移除」 | 不拉伸坏图、不显示错误资源地址，不丢文字 |
| 正在保存 | 「保存中」 | 不移动正文或自动关闭页面；保留最新编辑状态 |
| 已保存 | 短暂或安静的「已保存」 | 不每次弹 Toast、不连续打断读屏 |
| 未保存 | 「未保存」或明确待保存状态 | 返回不静默丢失；草稿机制另行实现验证 |
| 保存失败 | 深暖色图标 +「保存失败，内容仍保留」+「重试」 | 不只改变颜色；焦点留在可恢复内容，不清空输入 |
| 权限未允许 / 选择取消 | 简短说明，需要时引导系统设置；取消无需报错 | 正常记录仍可继续，不反复索取权限 |
| 动效关闭 / GPU 能力有限 | 同一母形的静态平面或预渲染版本 | 页面、记录、导航与编辑功能完整保留 |

误触防护和保存语义应先有清楚产品定义，再写交互代码。动画、自动收拢或卡片变形不能作为数据已保存的唯一反馈。

## 9. 3D、动效与性能边界

允许实时或预渲染 3D 的位置为：品牌展示中的单枚折光弧、首次空态的小形体、主操作的轻微反馈。普通页右上没有无作用的 3D 形，回顾页不另造装饰形体。原生文字、输入、导航、任务勾选、日历和照片均使用稳定的 2D 界面，不进入可拖转的三维空间。

3D 不是多摆几件真实物品。材质采用半透玉色与抽象切面，厚度轻、反射低，主光左上；不使用摄影背景、木桌、真实纸张、镜面金属、深景深或耀眼光斑。圆角、边缘和光线相互一致，不能同页混用一枚照片感玉石和一组粗糙扁平小图标。

动效基准：按钮按下 120 ms，原生页面切换 220 ms，与 `design-tokens.json` 一致；品牌形可采用受控的轻微入场，静态降级无需等待。以透明度和小幅位移解释关系；避免夸张弹簧、循环漂浮、输入时摇晃和以动画拖延保存反馈。具体 easing 由后续实现与实际设备审看确定，不提前绑定动画库。

性能和降级要求：

- 可见且正在动时才运行渲染，停留稳定状态后停止无意义循环；页面切走、App 进入后台或窗口不可见时释放/暂停相应资源。
- 在实际目标设备上测量启动、帧时间、内存与耗电。以稳定流畅为目标，不拿桌面浏览器结果证明 Android 性能；尚无原生实现时不宣称已达到 60 fps。
- 动画关闭、系统降低动效或用户选用静态模式时，显示同一构图的静态母形，取消旋转与视差；保存状态与页面语义照常可用。
- 使用静态降级的比例、颜色、轮廓与光线应和 3D 一致，不能变成完全不同的图标。没有 3D 能力也必须拥有完整识别度。
- 不为小图标启用持续多重透明渲染、大分辨率离屏折射或多个实时阴影。效果选择以实际设备预算和测量为依据。

## 10. 视觉设计稿与原生实现的区别

本轮交付的是品牌与页面设计方案：已完成两张概念设计板和确定性的品牌 / token 源稿；未开发 Android 界面，未生成 APK。生成的概念图可以探索材质、构图和气质，但其中的中文、图标、按钮尺寸、间距、日期和系统栏未必准确，也不能作为可运行界面或无障碍证明。每张图注明「UI / VI 概念稿 · 示例内容 · 非运行截图」。

正式实现之前需要重绘确定性的界面稿：可编辑文字、按 dp / sp 设置的布局、独立向量图标、清楚的状态组件和分离的品牌素材。品牌母形最终应交付平面 SVG / 可用向量资源、静态位图和需要时的 3D 资源；不能从一张大概念图裁出按钮、标题或系统状态栏。

原生渲染的验收必须来自 Android 模拟器和至少一台实际目标设备。截图与录屏要注明设备、逻辑尺寸、系统版本、字体缩放和界面状态；只有执行过的交互、数据恢复与性能结果才能写成「已验证」。本轮未生成 APK，也未执行 Android 性能和无障碍测试。

### 10.1 概念稿与实施 token 的差异

当前概念参考为 [UI / VI 总览 v02](ui-vi-overview-v02.png) 和 [状态板 v01](ui-states-v01.png)，两张实际文件已在本目录。总览展示品牌母形、调色板以及今天 / 全屏编辑 / 月历三页，已调整正文的 sans 方向、统一右上开口母形、将底部导航改为「今日 / 回顾 / 我的」，并删除各页右上无作用玉环。状态板展示空首页、键盘展开、深色探索与我的页面。图像来源与文件记录见 [image-provenance.json](image-provenance.json)。

图中的照片是生成的风景演示图，不是用户照片，也不是对真实历史绘画的复原。记录文字是构图示例，不作为默认数据。v02 已改善正文方向，但生成图片并未包含可验证的字体元数据，不能证明其中的每个文字都达到 Android sans / Noto Sans SC、16 sp 正文或准确的字重。正式渲染以本规范与 token 为准；衬线只用于少数短标题和字标，日期、月历数字、按钮及导航仍用 sans。

图像的手机比例、系统栏和日期按钮不能证明 360 / 412 dp、48 dp 命中范围或键盘安全区已经满足；辅助文字、浅边界和深色方案需要对最终渲染重新校正对比度。状态板的键盘只说明 IME 出现时的布局关系，真正实现由系统输入法提供，读取真实 insets；不制作 App 内假键盘，不固定键帽、候选条或键盘高度。

状态板「我的」页的备份图示意用了云形。正式组件应换成 archive / storage 语义的归档或存储图标，说明本地备份与恢复；本轮没有云同步设计承诺或已实现的云服务。「深色方案」已有预备色彩值，仍是视觉探索，尚未完成全状态和最终对比度验证，不能当作已交付的可用主题。

确定性源稿实际为同目录的 [brand-mark.svg](brand-mark.svg)、[app-icon.svg](app-icon.svg) 和 [design-tokens.json](design-tokens.json)。母形、颜色、字体角色、间距与深度用途以这些源稿和本规范为准，不能从生成图反向猜数值。其中 `app-icon.svg` 是静态图标预览，还不是已导出的 Android 自适应图标三层资源；正式实现需补齐前景、背景与单色层以及各系统遮罩检查。

可编辑界面规范稿 [ui-layouts.svg](ui-layouts.svg) 和 [components.svg](components.svg) 已交付，包含三页 412 × 892 dp 布局、品牌、组件与保存状态，文字与图形可编辑。已用 Inkscape 渲染并审看两张对应预览；它们用于确定性排版和组件说明，不是 Android 运行界面。保存失败、媒体读取失败、权限取消、200% 字号等已在本文定义，当前状态板没有完整逐屏绘出，仍属于下一步精稿内容。

页面草图若同时展示多个手机，应保持同一调色板、圆角、字重、光线与 icon 家族，不能三页分别采用三套美术。

### 11.3 原生实现后才可报告的检查

实际 48 dp 命中与不重叠日期单元；360 / 412 dp 无溢出；200% 字体不裁切；TalkBack 顺序与名称；系统返回和键盘行为；保存失败不丢输入；取消照片选择不添假数据；前后台切换与静态降级；目标设备性能与真实记录读写。检查必须针对最终构建，不能用旧网页测试通过代替。

审美评审需看实际图稿与原生画面，测试数量只能支持行为与约束，不能证明「高级」或「好看」。本轮先把品牌形、页面骨架、颜色与排版定下来，再进入可编辑精稿和原生实现，避免在同一套网页上继续做细小换色。
